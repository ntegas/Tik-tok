# Smart Money Tracker

Личный инструмент для одного пользователя: что делают отслеживаемые
инвесторы (13F) → пересекается ли это с моим watchlist/портфелем → что
происходит с моими деньгами. Не продукт, без аккаунтов, без монетизации —
подробные границы см. в описании задачи / истории обсуждения проекта.

Живёт как отдельная папка внутри `Tik-tok` (репозиторий изначально заведён
под другой личный проект — соцсети — но это тот же принцип: личные
инструменты Алексиса, не связанные продукты).

## Статус: шаг 1 из roadmap

> 1. Настроить EdgarTools, вытащить 13F для 3-5 инвесторов вручную,
>    убедиться что парсинг и CUSIP-маппинг работают корректно. ← **здесь**
> 2. Сравнение кварталов (NEW/ADD/REDUCE/EXIT/HOLD)
> 3. Watchlist и portfolio таблицы
> 4. Overlap-экран
> 5. UI поверх

Готово на шаге 1:
- `schema.sql` — investors/filings/holdings (+ watchlist/portfolio_transactions
  под шаг 3, таблицы созданы заранее по схеме из спеки, но пока не используются).
- `investors.py` — 5 инвесторов для валидации (Berkshire, Pershing Square,
  Renaissance, Point72, Bridgewater). CIK взяты из offline-датасета
  `edgar/reference/data/portfolio_managers.json`, который поставляется вместе
  с edgartools — не гадание, но и не подтверждено live-запросом к EDGAR (см.
  ограничение сети ниже). Финальный список 20-30 инвесторов для MVP собирается
  отдельно.
- `scripts/fetch_13f.py` — тянет последний 13F-HR/13F-HR/A через edgartools
  (`Company(cik).get_filings(...)` → `ThirteenF(filing).holdings`), фильтрует
  до long equity (без опционов), пишет в SQLite.
- `tests/test_pipeline_offline.py` — **прошли**, без сети: DB-слой (insert/
  upsert/идемпотентность), маппинг колонок holdings, и по-настоящему (не мок)
  offline CUSIP→ticker резолюция через встроенный в edgartools датасет
  `edgar/reference/data/ct.pq` — проверено на реальных CUSIP (AAPL
  `037833100`, KO `191216100`, BAC `060505104`), плюс что несуществующий
  CUSIP честно даёт `NULL`, а не выдуманный тикер.

### CUSIP → ticker: закрыт открытый вопрос из спеки

Спека помечала security master как открытый вопрос ("резолвить вручную,
не строить общий маппинг"). По факту решать не пришлось: edgartools несёт
с собой offline-таблицу CUSIP→Ticker (`cusip_ticker_mapping()`,
источник — проект `edgar-storage` того же автора) и использует её сама
внутри парсера 13F (`edgar/thirteenf/parsers/infotable_xml.py`). Она
покрывает основные акции, работает без сети и без своего ключа — то, что
нужно для 20-40 тикеров MVP. Что не резолвится — остаётся `NULL` в колонке
`ticker`, руками разбираем по мере необходимости, отдельный security-master
слой не строим.

### Ограничение текущей песочницы: data.sec.gov недоступен

`scripts/fetch_13f.py` не смог быть прогнан live здесь — исходящий трафик
на `data.sec.gov` блокируется политикой этого облачного окружения (403 от
gateway, не ошибка кода/ключа/CUSIP). Тот же паттерн уже был в этом
репозитории для Edge TTS, см. `../RUN_LOCALLY.md`.

Код и API-использование проверены по исходникам edgartools (структура
`ThirteenF.holdings`, `report_period`, `is_amendment` и т.д.) и офлайн-тестами
выше; сам HTTP-вызов к EDGAR не проверен end-to-end. Прогнать на машине с
обычным интернетом:

```bash
cd smart_money_tracker
pip install -r requirements.txt
cp .env.example .env   # вписать EDGAR_IDENTITY = "Имя email@example.com"
python3 scripts/fetch_13f.py
```

Если после первого live-прогона парсинг/маппинг разойдётся с ожиданиями —
это шаг 1 ещё не закрыт, разбираемся до перехода к шагу 2.

## Схема БД

См. `schema.sql`. `holdings.status`/`pct_change` пока всегда `NULL` —
считаются на шаге 2 (сравнение с предыдущим `filing` того же инвестора).
`filings.amendment_of` пока тоже не резолвится (шаг 2) — сейчас только
пишется флаг `is_amendment`.

## Известные ограничения (не забыть на будущих шагах)

- 13F ≠ весь портфель: только US-листингованный long equity, AUM >$100M,
  без шортов/опционов/бондов/кэша/международных активов, часть holdings
  может быть скрыта (confidential treatment).
- Amendments (`13F-HR/A`) могут переопределять более раннюю версию за тот
  же период — `amendment_of` обязателен перед сравнением кварталов (шаг 2),
  иначе сравнение даст ложные NEW/EXIT.
- Rate limits: 13F обновляется раз в квартал, чаще опрашивать бессмысленно.
